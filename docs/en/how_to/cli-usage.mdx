# Use the CLI

The CLI can run as a standalone tool or as a kubectl plugin.
You can copy it from the netobserv-controller-manager pod to your local machine.

Use the CLI for on-demand troubleshooting when you want to inspect packets or flows for a limited period.
It supports these two modes:

- TUI mode, which displays captured traffic in real time for interactive inspection
- Background mode, which starts a capture task and lets it continue until it reaches the configured stop condition or is stopped manually

Both modes support exporting capture results for offline analysis.

## Copy the CLI

Example:

```bash
# Get name of the NetObserv Controller Manager pod
CONTROLLER_POD=$(kubectl get pods -n netobserv-operator -l app=netobserv-operator -o jsonpath="{.items[0].metadata.name}")
# Copy the CLI from the controller manager pod to your local machine
kubectl cp netobserv-operator/$CONTROLLER_POD:/kubectl-netobserv /usr/local/bin/kubectl-netobserv
# Make the CLI executable
chmod +x /usr/local/bin/kubectl-netobserv
# Verify that the CLI is working
kubectl netobserv help
```

## Install or Copy yq

The CLI requires __yq__ on your local machine to modify YAML files.
If yq is not installed locally, you can copy the binary from the netobserv-controller-manager pod.

```bash
# Copy yq from the controller manager pod to your local machine
kubectl cp netobserv-operator/$CONTROLLER_POD:/yq /usr/local/bin/yq
# Make yq executable
chmod +x /usr/local/bin/yq
# Verify that yq is working
yq --version
```

:::note
The CLI uses some images packaged in the NetObserv Operator, but it does not require the NetObserv Operator to be installed to work.
After you prepare the CLI, you can uninstall the NetObserv Operator if you no longer need it. The CLI will continue to work.
:::

## View the Help Message

Before you start a capture task, review the available commands:

```bash
# Get help message for the CLI
kubectl netobserv help
# Get help message for packet capture command
kubectl netobserv packets help
# Get help message for flow capture command
kubectl netobserv flows help
```

## Enable Shell Completion

Generate completion for the shell you use; this command does not need cluster access:

```bash
# Bash, for the current shell session
source <(kubectl netobserv completion bash)
# Zsh, for the current shell session
source <(kubectl netobserv completion zsh)
```

Run only the line for your shell. Completion includes the packet-capture Deployment and Pod selector options.

## Capture Packets

Packet capture records raw packets that match the filters you specify.
Use packet capture when you need full packet details instead of summarized flow records.

:::note
If a packet length is greater than 256 bytes, the packet will be truncated in the capture results.
:::

The captured packets can be exported to a pcapng file for offline analysis with tools like Wireshark.

Example in Wireshark:

![Wireshark](../assets/netobserv-cli-packets-wireshark.png)

:::note
The captured packets are not sorted by timestamp in the pcapng file, so you may need to sort the packets by timestamp in Wireshark to analyze the packet flow.
:::

The packet comments include metadata such as node IP, interface name, and Kubernetes resource information.

You can filter packets in Wireshark based on these comments.
Example filter by node IP and interface name:

```txt
frame.comment == "AgentIP: 192.0.2.10" && frame.comment == "InterfaceName: ovn0"
```

In Kube-OVN overlay networking, packets between pods on different nodes are encapsulated with Geneve or VxLAN.
The original packet is carried as the payload of the Geneve or VxLAN packet.
To capture encapsulated traffic, use `--enable_geneve` or `--enable_vxlan` when running the packet capture command.

Example command for capturing TCP packets on port 8080, including Geneve-encapsulated packets:

```bash
kubectl netobserv packets --enable_geneve --protocol=TCP --port=8080
```

### Capture Traffic for Deployments or Selected Pods

Use `--deployment=namespace/name:port` to resolve the running Pods owned by a Deployment to their Pod IPs when the capture starts. For example, capture packets involving either the load balancer Pods on port 80 or the backend Pods on port 8080:

```bash
kubectl netobserv packets --deployment=shop/lb:80 --deployment=shop/app:8080 --protocol=TCP
```

Use `--pod-selector=namespace/labelSelector:port` for running Pods selected by labels instead:

```bash
kubectl netobserv packets '--pod-selector=shop/app.kubernetes.io/name in (frontend,api):8080' --protocol=TCP
```

Both options can be repeated or combined. Each target matches traffic with either endpoint at its Pod IP and the specified port; multiple targets are joined with OR, **not** limited to traffic between the listed workloads. The CLI prints the equivalent packet filter before it creates capture resources. Pod IPs are a snapshot: rerun the capture after a rollout to include replacement Pods. A selector without an eligible running Pod and Pod IP fails before creating resources.

These options are available for `packets`, not `flows`. Do not combine them with native CIDR, peer, or port filters, or a manual OR expression. The packet filter map defaults to 16 distinct Pod IPs. For more IPs, specify a sufficient capacity and use a packet agent image that supports it:

```bash
kubectl netobserv packets --deployment=shop/lb:80 --deployment=shop/app:8080 --filter-map-entries=32 --protocol=TCP
```

### Set Packet File Size

By default, packet capture does not split the pcap output. To write size-limited pcap shards, set `--split-bytes` on a `packets` capture:

```bash
kubectl netobserv packets --port=8080 --split-bytes=64KiB --copy
```

The value accepts a byte count or a size suffix such as `64KiB` or `500MB`; `--split-bytes=0` disables splitting. This option does not apply to `flows`.

### Limit Capture Duration and Total Size \{#limit-capture-duration-and-total-size}

Both packet and flow captures accept `--max-time` (default `5m`) and `--max-bytes` (default `50000000` bytes). For example, stop a packet capture after 15 minutes or when the overall capture reaches 500 MB, whichever happens first:

```bash
kubectl netobserv packets --background --port=8080 --max-time=15m --max-bytes=500MB
kubectl netobserv follow
# After capture stops, copy the output and remove the capture resources.
kubectl netobserv copy
kubectl netobserv cleanup
```

`--max-bytes` accepts a byte count or a size suffix such as `500MB` or `10G`; invalid sizes are rejected before capture resources are created. It limits the total capture, whereas `--split-bytes` controls each packet pcap shard. In background mode, reaching either limit stops the eBPF agents but leaves the collector available for `copy`; run `cleanup` after copying. The packet capture metadata reports `max_bytes_reached` if the overall size limit was reached. To stop an active background capture early, run `kubectl netobserv stop` before `copy`.

### Run Packet Capture in TUI Mode

Example command for TUI mode:

```bash
kubectl netobserv packets --cidr=198.51.100.77/32 --peer_ip=192.0.2.10 --protocol=TCP --port=8080
```

This command captures packets that match the specified filters and displays them in TUI mode.

Example TUI interface:

![Packet Capture TUI](../assets/netobserv-cli-packets-tui.png)

Press _CTRL+C_ to exit TUI mode and stop the packet capture.
By default, the CLI will ask you whether to export the captured packets to a pcapng file after you exit TUI mode.
You can use the `--copy` flag to save the pcapng file automatically without confirmation.

### Run Packet Capture in Background Mode

Example command for background mode:

```bash
kubectl netobserv packets --background --cidr=198.51.100.77/32 --peer_ip=192.0.2.10 --protocol=TCP --port=8080
```

This command starts a packet capture task in the background that captures packets matching the specified filters.

To copy captured packets to a pcapng file in background mode, run:

```bash
kubectl netobserv copy
```

When the capture task is stopped or finished, you can use the `cleanup` command to remove the background capture task and free up resources.

```bash
kubectl netobserv cleanup
```

## Capture Flows

Flow capture records summarized network flow data instead of raw packets.
Use it when you want traffic metadata and flow statistics rather than full packet payloads.

The usage of flow capture is similar to packet capture, but the results are exported in JSON and SQLite format instead of pcapng.

Example command:

```bash
kubectl netobserv flows --cidr=198.51.100.77/32 --peer_ip=192.0.2.10 --protocol=TCP --port=8080
```
